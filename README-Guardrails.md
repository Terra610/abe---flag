# A.B.E. Guardrails

## Core Constraints

The A.B.E. Engine MUST remain:

- Local-only
- Deterministic
- Non-predictive
- Non-persuasive
- Non-adaptive

It is NOT:
- AI
- probabilistic
- recommendation-based
- decision-making

It is a **calculation and structure verification system only**.

---

## Absolute Rules

1. No backend services
2. No user tracking
3. No login systems
4. No cloud processing
5. No hidden data handling

---

## Integrity Rules

- All outputs must be traceable to inputs
- All calculations must be reproducible
- No fabricated data
- No simulated outputs

---

## Doctrine Enforcement

Modules must not override doctrine.

If a module produces output outside doctrine:
→ it must be flagged as divergence

---

## Expansion Rule

New modules must:
- align with doctrine
- use deterministic logic
- maintain local-only execution

---

## System Identity

A.B.E. is:

- a structural verification engine
- a constitutional alignment framework
- the first implementation of Constitutional Systems Engineering

---

## Non-Negotiable

If any feature violates:
- transparency
- determinism
- locality

It must not be implemented.
